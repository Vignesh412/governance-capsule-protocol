# Cross-Framework Governed Delegation Spec

## Overview

Build a local, reproducible cross-framework proof in which an originating agent boundary modeled on the OpenAI Agents SDK delegates a supplier-onboarding task through a signed Governance Capsule to a receiving Google ADK agent boundary.

GCP, not either framework's conversational state, is the authoritative carrier of delegated authority, mandatory obligations, budget, revocation requirements, lineage, and enforcement evidence. The receiving boundary must reject invalid governance before its agent tool or the protected supplier connector is invoked.

This milestone remains a local prototype and does not include cloud deployment or production credentials. It now adds an optional **Live Native Mode** using real OpenAI Agents SDK and Google ADK model runs. The deterministic interoperability contract remains the default CI path and requires no API keys.

## Example Use Cases

### Valid cross-framework delegation

1. An OpenAI-side procurement agent is authorized to create suppliers under `urn:supplier:*`, must produce an audit event, and has a $10 cost budget.
2. It delegates creation of `urn:supplier:42` to a Google ADK Supplier Operations agent with a $2 child budget.
3. The OpenAI adapter emits a signed, framework-neutral GCP transport envelope.
4. The ADK adapter imports and verifies the envelope before exposing the protected supplier tool.
5. The governed gateway commits the supplier once and emits a signed receipt containing both framework-boundary evidence records.

### Invalid authority expansion

The receiving-side task asks for `supplier.delete`, which the parent never possessed. The ADK boundary rejects the handoff before the ADK tool callback and supplier connector are called.

### Mandatory obligation removal

The child capsule omits the parent's required audit obligation. The receiving boundary rejects the handoff before agent execution.

### Cascading revocation

The root capsule is revoked after transport but before the receiving action boundary. The downstream action is rejected.

### Valid contract with unsafe runtime evidence

The OpenAI-to-Google delegation is structurally, cryptographically, and
semantically valid. Before connector access, a trusted screening result reports
an unresolved possible sanctions match. GCP must report the delegation as
verified; CARM must preserve the regulatory-versus-organizational policy
conflict and require human approval; the connector must remain untouched.

## Tools Required

### GCP transport envelope

A deterministic JSON object containing:

- transport profile and version;
- source and destination framework identifiers;
- action proposal;
- ordered capsule lineage and delegation proofs;
- artifact digests;
- transport creation time and nonce; and
- transport signature.

### OpenAI Agents SDK adapter

An optional adapter compatible with an OpenAI handoff callback and local run context. It exports the GCP transport envelope from application-owned governance state. It must not treat conversation history or model-generated handoff metadata as delegated authority.

### Google ADK adapter

An optional adapter compatible with an ADK callback/tool boundary. It imports the transport envelope, verifies GCP semantics, and makes the protected tool unavailable when verification fails.

### Governed Action Gateway

The existing gateway remains the only component authorized to call the supplier connector.

No external business API is required. The in-memory idempotent supplier connector remains the protected side effect for this milestone.

## Constraints & Safety Rules

- A model response, prompt, conversation history, or framework session field cannot grant authority.
- Native agent execution must not begin until envelope structure, signatures, lineage, audience, time validity, revocation freshness, authority attenuation, obligation persistence, and budget containment pass.
- The Google-side protected tool must not be exposed or called after failed GCP verification.
- The supplier connector remains inaccessible except through the Governed Action Gateway.
- Framework adapters may add evidence but cannot relax GCP decisions.
- Unknown critical transport fields or unsupported semantics fail closed.
- Transport nonces are replay-protected and bound to the exact proposal and lineage digests.
- Tests must be deterministic and must not assert on nondeterministic LLM prose.
- Live SDK tests are optional integration gates and must be clearly separated from the offline contract suite.
- No API key, cloud deployment, external message, or public release is authorized by this milestone.

## Success Criteria

1. A signed task crosses two distinct framework adapter boundaries and commits exactly once.
2. The receiving adapter verifies the same GCP semantics already enforced by the reference kernel.
3. Authority expansion, obligation removal, proof tampering, replay, and root revocation all stop before the receiving tool and connector.
4. The enforcement receipt identifies the source adapter, destination adapter, transport digest, verified lineage, decision, and connector result.
5. The full deterministic proof runs locally and in CI without API credentials.
6. Optional native OpenAI and Google ADK contract tests demonstrate compatibility with installed SDK surfaces when their extras are available.
7. The visual demo clearly shows the framework boundary, portable capsule, receiving verification, failure boundary, and signed evidence.
8. A developer can run the proof with one documented command.
9. Live Native Mode executes an OpenAI tool invocation and a Google ADK protected-tool request while keeping governance outside model-generated state.
10. The browser receives progressive runtime events and clearly distinguishes native execution from deterministic replay.
11. Missing SDKs or credentials fail with an actionable readiness report and zero connector calls.
12. The visual demo distinguishes `GCP VERIFIED`, `CARM RISK_DETECTED`, and `ACTION PAUSED` for a valid-but-risky request.
13. Runtime-risk evidence cannot modify the signed delegation contract, and a valid contract cannot bypass local risk policy.

## Architecture & Agents

- **Originating boundary:** OpenAI Agents SDK adapter profile.
- **Transport:** signed GCP cross-framework envelope.
- **Receiving boundary:** Google ADK adapter profile.
- **Policy and enforcement:** existing GCP kernel, Governance Graph, CARM, and Governed Action Gateway.
- **Side effect:** idempotent supplier connector.

The adapters are translation and interception boundaries, not alternate policy engines.

## Deployment Preference

Prototype first. Run locally with deterministic framework contracts plus an optional credentialed native showcase. Cloud deployment, Agent Runtime, Cloud Run, GKE, and public hosting remain outside this milestone.

## Evaluation

- Use `pytest` for deterministic transport, adapter, security-boundary, and connector-call correctness.
- Add native SDK smoke tests behind optional dependency markers.
- If live model-driven agents are introduced later, use framework evaluation tooling rather than asserting on generated response text in unit tests.

## Reference Sources

- OpenAI Agents SDK handoffs: application callbacks receive local run context and optional structured handoff input; existing application state belongs in local context rather than model-generated handoff metadata.
- OpenAI Agents SDK guardrail boundary: handoffs stay within one run, so GCP must explicitly enforce governance at the external framework boundary.
- Google ADK Python agent callbacks and tool boundaries will be confirmed against the scaffolded SDK version before native adapter implementation.
